# Emberwood 2.0.0 — 100-day survival

User wants Thai throughout, responsive on device sizes, a verified latest version, more selectable minigames, upgradeable weapons, a 100-day survival goal and progressively stronger monsters. User explicitly selected combat, dodging and target-shooting minigames.

## Architecture / ownership

- Root owns `emberwood.html`, campaign engine, weapons, save/load, integration and existing tests. Preserve the procedural visual style and offline single HTML runtime. Backup: `handoff/emberwood-before-100-days.html`.
- Independent minigame agent owns ONLY `C:/Users/kkriangkai/AppData/Local/Temp/emberwood-minigames-v2.js` and `D:/Games/tests/minigames.test.cjs`. Root embeds the finished module into the existing game-logic script. No HTML edits by that agent.

- All game decisions/rewards belong to the engine. UI emits intents and renders owner-provided data; minigames are real timed simulations, not prepared fixtures. No network or external images/libraries/fonts.

## Minigame module contract

Standalone JS (no DOM) exports `window.EmberwoodMiniGames = { CombatMiniGame }`.

`new CombatMiniGame({type,day,seed,id})` with type `targets|dodge|duel`; methods `update(dt)`, `setInput(x,y)`, `act({action,x,y})`, `snapshot()`, `getResult()` (null until finished), `serialize()`, static `restore(data)` (throws for malformed saves). Public `finished` boolean; id is included in snapshot/serialized data. Fixed logical arena width=360,height=220. update is dt-based and bounded. Rewards are NOT calculated here.

Common snapshot: `{id,type,elapsed,duration,finished,score,maxScore,success,message, player?,hazards?,targets?,cue?}`. Points in 360×220 coordinates. `targets:[{id,x,y,r}]`; `player:{x,y,r,hp,maxHp,invincible?}`; `hazards:[{id,x,y,r}]`; duel `cue:{phase:'windup'|'parry'|'recovery',progress,windowStart,windowEnd,round,totalRounds}`. Result `{score,maxScore,quality:0..1,success}`. Root applies resource/health rewards once.

- Targets: click moving bullseyes, `act({action:'shoot',x,y})`; 10 hits or ~20 sec, misses lower quality. Must reject NaN/out-of-arena actions.
- Dodge: 15 sec, directional setInput, 3 HP, incoming bullets, collision i-frames, no out-of-bounds, finite hazard lifetime/count, keyboard and touch controlled by UI.
- Duel: 5 rounds, randomized windup followed by short visible parry window; `act({action:'parry'})` / Space; early/late attempts fail the round. Actual timing determines score.

Agent tests may use `EMBERWOOD_MINI_SOURCE` to load temp module during work; normal default must extract script id=game-logic from final HTML and read the export. Test genuine hits/misses, dodging/collision/expiry, duel timing, no actions after finish, deterministic serialize/restore and corrupt input.

## Campaign UI factory contract

Temp JS exports `window.EmberwoodCampaignUI={create}`. `create({emit,onMenuState,isBlocked,art})` returns methods:

`update(campaign,miniGame)`, `openStartMenu(options)`, `openWeaponMenu()`, `openMiniHub()`, `closeMiniHub()`, `openMiniGame(view)`, `closeMiniGame()`, `openDayChoice(request)`, `closeDayChoice()`.

Root will add these dialogs to existing blocked/closeMenus/close event handling. Factory MUST NOT add duplicate global dialog-close handlers. On showing a dialog call `onMenuState(menuName,true)`; closing `.close()` is picked up by root. Dialog IDs/names: startDialog/start, weaponDialog/weapon, miniHubDialog/miniHub, miniGameDialog/miniGame, dayChoiceDialog/dayChoice. All have `data-campaign-dialog`. Root spreads returned methods onto `EmberwoodUI` and calls update on snapshot sync.

`art.drawWeaponIcon(ctx,id,x,y,scale)` will be supplied (axe/spear/bow); `art.drawResource(ctx,type,x,y,scale)` is supplied. Other mini visuals must use Canvas shapes. No emoji asset reliance.

Campaign data:

```js
{version:'2.0.0',day:1,totalDays:100,phase:'running',equipped:'axe',
 resources:{coins:50,gems:0,wood:13},miniAvailable:true,miniUsedToday:false,
 weapons:[{id:'axe',name:'ขวานวงเหวี่ยง',level:1,maxLevel:10,damage:10,interval:1.5,range:78,
 upgradeCost:{coins:25,gems:0},canUpgrade:true,selected:true}, /* spear,bow */]}
```

Start options `{hasSave,saveDay,version,selectedWeapon}`. Start selects one of three weapons and emits `campaign:new {weaponId}`; if hasSave, show `campaign:resume` and require a clear inline confirmation before replacing progress with a new campaign. No native confirm/alert. Weapon card actions `weapon:equip {weaponId}`, `weapon:upgrade {weaponId}`. Mini hub actions `mini:start {miniType}`; disabled with explanation when daily attempt already used. Main HUD buttons open weapons and mini hub; show version in settings/intro, all labels Thai.

Mini actions: `mini:input {gameId,action:'shoot'|'parry'|'move',x,y}`. move x/y normalized [-1,1]. Support keyboard arrows/WASD for dodge, touch dragging and/or ≥44px directional buttons. Canvas pointer coordinates mapped to 360×220. Space parries only while duel active. `mini:cancel {gameId}` exits with daily attempt used; `mini:close {gameId}` acknowledges finished result. On finish show owner-provided `miniGame.rewardText` and button รับรางวัลและกลับ (engine already commits reward once). No client-side score/reward calculation.

Day request `{requestId,day,options:[{id,title,description,icon}]}` exactly 3. Emit `day:select {requestId,choiceId}`. Cancel should not bypass mandatory choice (prevent cancel). UI icons can be small procedural symbols. Responsive scroll inside larger dialogs, no horizontal overflow; fit 280×560,320×480,392×533,375×812,768×1024,844×390,1280×720,1920×1080. No fixed portrait page border.

## Main campaign decisions

- Default 100 days; a day ends when its encounter is defeated, with one mandatory 3-option survival reward and then a short break. Winning requires finishing day100; losing at 0 HP. Boss every10 days. Monster count capped (performance) but HP/speed/damage and types scale with day.
- Axe, spear, bow selectable and upgradeable to level10 using coins/gems. Preserve 30-log first building, 60-log first tower upgrade. Add bounded daily perks and distinct enemy variants.
- One combat minigame attempt per day; chosen mini freezes main simulation but has its own clock; menus/blur pause mini clock too. Owner computes rewards once, cancel consumes attempt, next day resets availability.
- Autosave locally, explicit continue/new on intro, schema version2, validate corrupt/incompatible saves. Preserve pending build/day choices and mini state on save/resume without duplicated reward, no stuck input. User progress is not replaced until new-campaign confirmation.
- All unseen balance is marked ASSUMPTION in CONFIG/notes.
