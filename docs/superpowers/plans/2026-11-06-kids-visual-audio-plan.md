# Emberwood 2.1 — เด็ก 7–15 ปี ภาพนำและเสียงครบ

ผู้ใช้อนุญาตให้ปรับทั้งระบบ: เข้าใจด้วยภาพเป็นหลัก ข้อความที่จำเป็นสั้นและใหญ่ พร้อมเสียงครบ รักษา HTML ไฟล์เดียวและเกมเอาชีวิตรอด 100 วัน

## แนวทาง

- ใช้ภาพ Canvas ของตัวละคร/กองไฟ/อาวุธเดิมเป็นภาษาเดียวกันทั้งเมนู ลดข้อความยาวเป็นภาพ+คำสั้น หัวข้อ 24–32px ข้อความใช้งาน 18–22px ปุ่มอย่างน้อย 52px
- HUD แสดงวัน ชีวิต ทรัพยากร และทางเข้าอาวุธ/ฝึกด้วยไอคอน ใช้สีและรูปทรงร่วมกัน เพิ่มคู่มือภาพ 3 ขั้น เดิน → เก็บ → สร้าง แสดงเป้าหมาย 100 วันอย่างชัดเจน
- การ์ดเลือกอาวุธ/ป้อม/พร/มินิเกมเน้นรูปใหญ่ เลือกแล้วมีเครื่องหมายถูก ราคามีรูปเหรียญ/อัญมณีและตัวเลข คำอธิบายเต็มอยู่ในชื่อที่โปรแกรมอ่านหน้าจออ่านได้
- มินิเกมคงกติกาเดิม แต่ใช้คำสั่งสั้น คะแนน/เวลาตัวใหญ่ รางวัลเป็นภาพและจำนวน ชัยชนะ/พลาดมีภาพและเสียง จึงยังเข้าใจได้เมื่อปิดเสียง
- เสียงสังเคราะห์ Web Audio ในไฟล์: ดนตรีอบอุ่น เสียงกองไฟ เมนู เริ่มเกม อาวุธสามแบบ โดนโจมตี กำจัดศัตรู เก็บของ ฝากไม้ สร้าง/อัปเกรด ผ่านวัน/บอส และมินิเกมทั้งสาม
- เริ่มเสียงเมื่อแตะ/กดครั้งแรกตามข้อจำกัดเบราว์เซอร์ มีปุ่มปิดเสียง ดนตรี/เอฟเฟกต์แยก ระดับเสียง และลองเสียง หยุดเสียงเมื่อไปแอปอื่น จำกัดเสียงซ้อนและเสียงถี่
- เซฟ schema 2 ใช้ต่อได้ การตั้งค่าเสียงเก็บต่างหาก ไม่เปลี่ยนเป้าหมาย 100 วันหรือความก้าวหน้าเดิม

## แบ่งงานและขอบเขต

1. ผู้ช่วย audio เขียนเฉพาะ Temp module + tests/audio.test.cjs ไม่แก้ไฟล์เกม
2. ผู้ช่วย campaign เขียนเฉพาะ Temp CampaignUI/CSS ไม่แก้ไฟล์เกม
3. Root ทำ HUD/คู่มือภาพ/เมนูป้อม/ตั้งค่า/เสียงเหตุการณ์/รางวัลแบบภาพ รวมทั้งหมดใน HTML และตรวจจริง

## หลักฐานก่อนส่งมอบ

- ทดสอบระบบเสียง (ปลดล็อก ปิดเสียง แยกเพลง/เอฟเฟกต์ inactive จำกัดเสียง การตั้งค่าชำรุด) และเหตุการณ์เสียงเกมโดยไม่เปลี่ยนสมดุล
- ชุดเดิมของเกม/เซฟ/100 วัน/มินิเกมต้องผ่าน
- ตรวจ browser จอแคบ 280/320/392, มือถือแนวตั้ง 375×812, แนวนอน 844×390, แท็บเล็ต/เดสก์ท็อป ตรวจปุ่มสนามฝึกยังเห็นพร้อมสนาม
- ตรวจไม่มี console error หลังเริ่ม และปุ่มลองเสียงทำให้มิเตอร์จากสัญญาณเสียงขยับจริง เก็บภาพหน้าจอสำหรับผู้ใช้

ไม่มีไฟล์ภาพ/เสียงภายนอก ไม่มีบริการเครือข่าย และไม่เพิ่มข้อความยาวในขั้นตอนเล่น
